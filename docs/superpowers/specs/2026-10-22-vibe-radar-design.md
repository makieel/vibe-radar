# vibe/radar — 개발 트렌드 대시보드 리빌드 설계

작성일: 2026-10-22
참고 원본: https://jihoo12.github.io/trends/ (`jihoo12/trends`, Apache-2.0)
디자인 시안: `design/mockup-v2-AplusC.html`의 **E · 오로라 HUD** 탭
논의 기록: `design/notes.md`

## 1. 왜 만드는가

원본 사이트는 Hacker News, GitHub Trending, arXiv를 매일 수집해 보여주는 정적 대시보드다. 사용자가 느낀 문제는 두 가지다.

- **디자인이 심심하다.** 회색 카드와 작은 막대그래프뿐이라 눈에 들어오는 게 없다.
- **자료가 부족하다.** 출처가 세 곳이고, 항목마다 제목과 숫자만 있어 읽을 거리가 없다.

사용자는 **바이브코딩하는 사람이 매일 아침 열어보고 싶은 페이지**를 원한다. 오늘 무슨 일이 터졌는지, 내가 쓰는 AI 코딩 도구에 무엇이 바뀌었는지, 지금 조심해야 할 보안 사고가 있는지, 새로 쓸 만한 재료가 무엇인지를 한 화면에서 보여줘야 한다.

원본 분석에서 확인한 약점도 함께 고친다.
- 키워드가 단순 빈도라 `thought`, `uncover` 같은 의미 없는 단어가 상위에 올라온다.
- 스타 추이가 트렌딩에 오른 날만 기록돼 그래프가 끊긴다.
- 출처끼리 연결되지 않는다.
- 지난 날짜를 볼 수 없다.

## 2. 목표 · 하지 않을 것 · 실패로 보는 것

### 목표
1. E · 오로라 HUD 시안의 느낌을 살린 실제 사이트를 만든다. 오로라 그라데이션, 모서리를 깎은 HUD 패널, 열기 게이지, 스캔 라인, 핫이슈 1면이 들어간다.
2. 사용자가 고른 콘텐츠 6가지를 모두 넣는다. (사용자: "전부 다 필요")
   1. AI 코딩 도구 업데이트 소식
   2. 바이브코딩 재료 창고 (MCP 서버, 에이전트 스킬·플러그인, 룰 파일 모음)
   3. 오늘의 핫이슈 (여러 출처에 동시에 뜬 주제를 이슈로 묶음)
   4. 보안 경보
   5. 출처 확대 (GeekNews, Hugging Face, Reddit)
   6. AI 한국어 요약
3. 원본의 약점 4가지를 고친다(1장 참고).
4. **다른 스타일로 갈아끼울 수 있는 구조로 만든다.** 사용자가 다음에 D나 F 같은 다른 스타일로도 만들기를 원한다.
5. 매일 자동으로 갱신되고, 서버 비용 없이 운영된다.

### 이번에 하지 않을 것
- 영어 지원. 한국어만 지원한다. (내 판단: 원본에는 한/영 전환이 있었지만 사용자가 한국어 사용자다.)
- 로그인, 개인화, 알림, 댓글
- 전체 검색(⌘K). D 시안에 있던 기능이고 E에는 없다. 구조만 막지 않는다.
- 스타일 전환 UI. 이번에는 E 하나만 만든다. 테마를 더 붙일 수 있는 구조만 갖춘다.

### 실패로 보는 것 (돌아가도 실패)
- 화려하지만 읽기 어렵거나 느린 페이지. 애니메이션 때문에 글자가 안 읽히거나 모바일에서 버벅이면 실패다.
- 시안의 `예시` 데이터처럼 **지어낸 값이 실제 사이트에 나가는 것.** 데이터가 없으면 없다고 보여준다.
- 출처 하나가 실패해서 하루치 수집 전체가 멈추는 것
- 유료 API 키가 있어야만 돌아가는 것
- 원본과 똑같은 회색 대시보드에 색만 바꾼 것

## 3. 제약

- **사용자 본인의 새 GitHub 저장소에 올린다.** (사용자 결정) 원본을 포크하지 않는다.
- 이 PC에는 `gh` CLI가 없다. 저장소 생성과 Pages 활성화는 사용자가 GitHub 웹에서 하거나, 그때 `gh` 설치를 다시 논의한다.
- 유료 API 키를 쓰지 않는다. GitHub Actions의 기본 `GITHUB_TOKEN`만 쓴다.
- **로컬 실행은 토큰 없이 축소 모드로 한다.** (사용자 결정)
  - GitHub API는 토큰이 없으면 시간당 60회로 제한된다. 그래서 축소 모드에서는 다음을 줄인다.
    - 스타 추적 대상 수
    - 재료 검색 횟수
    - 릴리즈·권고 조회
  - 줄인 부분은 화면에 "축소 모드"로 표시한다.
  - `GITHUB_TOKEN` 환경변수가 있으면 전체 모드로 돈다. Actions에서는 항상 전체 모드다.
  - 로컬에서는 AI 요약과 번역을 건너뛴다. 원문을 보여준다.
- **AI 요약(GitHub Models)은 저장소에 올린 뒤 Actions에서 처음 확인한다.** (사용자 결정) 확인 전까지는 요약 단계가 실패해도 페이지가 정상으로 나와야 한다.
- **저장소는 공개로 만든다고 가정한다.** (내 판단) 무료 GitHub 계정은 비공개 저장소에서 Pages를 쓸 수 없기 때문이다. 사용자가 다르게 정하면 바꾼다.
- 로컬 환경: Node v24.21.0, npm 11.19.0, git 2.55
- 작업 폴더: `F:\VibeCoding\trends-rebuild\`
- 원본 코드를 복사하지 않고 새로 작성한다. README에 원본에서 아이디어를 얻었다고 적는다. (내 판단: 라이선스 문제를 피하기 위해서다.)

## 4. 사용자가 정한 것

- 디자인은 E · 오로라 HUD로 한다. 시안에서 쓴 화면 구성 요소는 다음과 같다.
  - 상단 내비게이션: 로고 `vibe/radar`, 메뉴(브리핑·도구·재료·레포·논문), 수집 시각과 회차 표시
  - "오늘의 개발판 열기" 원형 게이지(0~100)와 한 줄 해설, 7일 평균 비교
  - 1면 핫이슈: 큰 제목, AI 요약 본문, "바이브코더 체크" 한 줄, 2~4위 이슈 바로가기, 스캔 라인 애니메이션
  - 보안 경보 띠: 깜빡이는 점과 빨간 패널
  - 3열 HUD 패널: AI 코딩 도구, 급상승 레포(7일), 바이브코딩 재료
- 콘텐츠 6가지를 모두 넣는다.
- 나중에 다른 스타일로 바꿀 수 있어야 한다.
- 새 저장소에 올린다.
- **라이트 모드와 다크 모드를 모두 지원하고, 토글 버튼으로 바꾼다.** 시안은 `design/mockup-v3-E-light-dark.html`이다.
  - 라이트 모드는 옅은 회청색 바탕(`#f3f5fc`) 위에 연한 오로라와 반투명 흰 HUD 패널을 쓴다. 강조색은 같은 계열에서 진하게 바꾼다(청록 `#0e7490`, 보라 `#6d28d9`, 분홍 `#a21caf`).
  - 다크 모드는 시안 E 그대로다.
  - 토글 버튼은 상단 내비게이션 오른쪽 끝에 둔다. 해와 달 아이콘이 있는 스위치다.

## 5. 내가 정한 것 (사용자가 바꿀 수 있음)

### 5.1 기술 구성
원본과 같은 방식으로 간다. 서버 없이 정적 사이트로 운영한다.

- **수집·가공:** Node 24 + TypeScript. Node의 타입 스트리핑으로 빌드 없이 `.ts`를 바로 실행한다.
- **실행:** GitHub Actions가 매일 00:00 UTC(09:00 KST)에 실행한다. 수동 실행도 가능하게 한다.
- **저장:** 날짜별 원본 스냅샷을 저장소에 커밋한다. 화면용 데이터는 빌드 때 만든다.
- **배포:** GitHub Pages
- **화면:** 프레임워크 없이 HTML, CSS, 브라우저 ES 모듈로 만든다. 빌드 단계가 없어야 테마 추가가 쉽고, 시안 HTML을 그대로 옮기기 좋다.
- 작업명은 `vibe-radar`로 한다. 시안의 로고에서 따왔다.

### 5.2 데이터 흐름

```
[수집] collect     출처별 수집기 → data/raw/YYYY-MM-DD.json   (KST 날짜, 같은 날 재실행 시 덮어씀)
[가공] analyze     핫이슈 묶기, 열기 점수, 키워드, 보안 경보, 스타 추이 → data/daily/YYYY-MM-DD.json
[요약] summarize   GitHub Models로 핫이슈 한국어 요약 → daily 파일에 채움 (실패해도 진행)
[빌드] build       최근 90일 → web/data/latest.json, web/data/index.json, web/data/days/YYYY-MM-DD.json
[배포] Pages       web/ 폴더 전체
```

- **출처별 독립 실패:** 수집기마다 성공/실패/건수를 기록한다. 실패한 출처는 그날 비어 있고, 화면 상단에 출처 상태(예: `● 6/7 출처`)로 보여준다.
- **화면 데이터 계약:** 테마는 `web/data/*.json`만 읽는다. 이 JSON 형식(스키마)이 데이터 쪽과 화면 쪽 사이의 유일한 약속이다. 스키마는 TypeScript 타입으로 한 곳에 정의하고, 빌드 때 검증한다.

### 5.3 출처와 수집 방법

| 출처 | 방법 | 확인 결과 (2026-10-22, 이 PC에서) |
|---|---|---|
| Hacker News 상위 30 | 공식 Firebase API | 200 |
| GitHub Trending 일간·주간 | `github.com/trending` HTML 파싱 (API 없음) | 200 |
| arXiv 최신 (cs.*, stat.ML) | arXiv API | 원본에서 사용 중 |
| GeekNews | RSS `news.hada.io/rss/news` | 200 |
| Hugging Face 트렌딩 모델 | `huggingface.co/api/models?sort=trendingScore` | 200 |
| Reddit r/ClaudeAI, r/vibecoding | RSS (`/top/.rss?t=day`). JSON은 403이라 쓰지 않음 | RSS 200 |
| AI 코딩 도구 릴리즈 | Claude Code·Codex·Gemini CLI는 GitHub Releases API, Copilot은 `github.blog/changelog/feed/`에서 Copilot 항목 필터, Cursor는 `cursor.com/changelog` 파싱 | 모두 200 |
| 보안 권고 | GitHub Advisory API (`/advisories`) | 200 |
| 레포 스타 수 | GitHub REST API (`GITHUB_TOKEN`) | — |

- **Reddit 주의:** GitHub Actions 서버 IP를 Reddit이 막을 수 있다. 그래서 "가능하면 수집하는" 출처로 둔다. 막히면 그날 비워 두고 출처 상태에 표시한다.
- **추적할 도구와 재료 검색어는 설정 파일 하나에 모은다.** 사용자가 도구를 추가하거나 빼기 쉽게 하기 위해서다.

### 5.4 기능별 규칙

**오늘의 핫이슈**
- 같은 주제를 다룬 항목을 출처에 상관없이 하나의 이슈로 묶는다.
- 묶는 기준은 같은 URL·도메인, 같은 레포 이름, 제목 핵심어 겹침이다.
- 이슈마다 열기 점수(0~100)를 매긴다. 재료는 HN 점수와 댓글, 등장한 출처 수, 스타 증가량이다.
- 상위 1개는 1면에, 2~4위는 바로가기로 보여준다.
- **점수 공식은 설명할 수 있어야 한다.** 화면에서 "왜 이 점수인지"를 짧게 보여줄 수 있어야 한다. 정확한 가중치는 만드는 사람이 정한다.

**오늘의 개발판 열기 (게이지)**
- 그날 상위 이슈들의 열기를 0~100으로 요약한 값이다.
- 지난 7일 평균과 비교해 "평소보다 뜨거움 / 평소 수준 / 조용함"을 표시한다.
- 데이터가 7일이 안 되면 비교 문구를 숨긴다.

**보안 경보**
- 두 가지에서 찾는다.
  - GitHub Advisory의 지난 24시간 critical·high 권고. 생태계는 npm과 pip이다.
  - HN과 GeekNews에서 보안 단어(backdoor, compromised, CVE, 취약점, 악성 등)가 들어간 글
- 최대 3건을 보여준다. 없으면 띠를 숨긴다. 가짜 경보를 만들지 않는다.

**AI 코딩 도구**
- 대상은 Claude Code, Cursor, Codex CLI, Gemini CLI, GitHub Copilot이다.
- 최신 버전, 배포 시각, 변경점 한 줄을 보여준다. 변경점은 릴리즈 노트 첫 항목 또는 AI 요약이다.
- 최근 7일 안에 새 버전이 나온 도구를 위로 올린다.

**바이브코딩 재료**
- 두 곳에서 모은다.
  - GitHub 검색: 최근 30일 안에 만들어지고 토픽이 `mcp`, `mcp-server`, `claude-code`, `agent-skills`, `cursor-rules` 등인 레포를 스타순으로
  - 트렌딩 레포 중 같은 토픽이나 키워드를 가진 것
- 종류 딱지를 붙인다: SKILL, MCP, RULES, CLI 등

**급상승 레포**
- 7일 스타 증가량 상위를 보여준다.
- **한 번이라도 트렌딩에 오른 레포는 이후 매일 스타 수를 API로 기록한다.** 원본의 "트렌딩에 오른 날만 기록" 문제를 고치기 위해서다.
- 추적 대상이 너무 많아지면 최근 30일 안에 트렌딩에 오른 레포로 제한한다.

**키워드**
- 불용어를 제거하고 두 단어 구문(예: "world model", "supply chain")을 지원한다.
- 7일 평균과 비교해 급상승한 키워드를 보여준다.

**AI 한국어 요약**
- GitHub Actions 안에서 GitHub Models API를 쓴다. 워크플로에 `permissions: models: read`를 주고 `GITHUB_TOKEN`으로 호출한다.
- 요약 대상은 상위 이슈 3~5개다. 이슈마다 2~3문장 요약과 "바이브코더 체크" 한 줄을 만든다.
- 실패하거나 사용 한도에 걸리면 요약 없이 원래 제목과 출처만 보여준다. 수집은 계속한다.
- 첫 구현 때 이 방식이 실제로 동작하는지 먼저 확인한다. 안 되면 사용자와 다시 정한다.

**한국어로 보여줄 범위** (내 판단, 검토에서 나온 질문)
- 시안처럼 화면에 보이는 짧은 문구는 한국어로 보여준다. 대상은 다음과 같다.
  - 1면 제목
  - 도구 변경점 한 줄
  - 재료·레포 설명 한 줄
  - 보안 경보 제목
- 번역은 하루 한두 번의 묶음 호출로 처리한다.
- 번역 결과는 항목 ID(레포 이름, 릴리즈 ID, 권고 ID)로 저장해 두고 다시 쓴다. 매일 새로 번역하는 건 새 항목뿐이다.
- 데이터에는 원문과 한국어를 함께 둔다(`title`, `title_ko`). 번역이 없으면 원문을 보여준다.
- HN, GeekNews, Reddit, arXiv 원문 목록의 제목은 번역하지 않고 원문 그대로 둔다.

**처음 며칠, 기록이 쌓이기 전** (내 판단)
- 7일 스타 증가량은 우리 기록이 7일치 쌓일 때까지 GitHub Trending 주간 페이지의 "stars this week" 값을 쓴다. 원본 사이트도 같은 방식이다. 이렇게 쓴 값에는 출처 표시를 붙인다.
- 게이지의 7일 비교, 키워드 급상승, 날짜 선택은 기록이 모자라면 "기록 쌓는 중 (n/7일)"으로 표시한다.
- 원본 저장소의 데이터는 가져오지 않는다.

**보안 경보 기준 강화** (내 판단)
- 띠에 올리는 조건은 둘 중 하나다.
  - 뉴스(HN, GeekNews)에 보안 단어와 함께 등장한 사고
  - 감시 목록에 있는 패키지의 critical·high 권고
- 감시 목록은 설정 파일로 관리한다. AI·바이브코딩에서 많이 쓰는 패키지로 시작한다. 예: `litellm`, `openai`, `anthropic`, `langchain`, `next`, `vite`, `express`
- 출처가 GitHub Advisory 하나뿐인 malware 유형 권고는 띠에 올리지 않는다. 매일 수백 건이라 소음이 되기 때문이다.

**지난 날짜 보기**
- 날짜를 골라 그날의 브리핑을 볼 수 있다. 최근 90일까지 된다.

### 5.5 화면 구성 (E 테마)

- **메뉴는 해시 주소로 나눈다.**
  - 브리핑 `#/`: 게이지, 1면, 보안, 3열 패널
  - 도구 `#/tools`
  - 재료 `#/kit`
  - 레포 `#/repos`: 급상승, 신규·이탈, 스타 추이 그래프
  - 논문 `#/papers`: arXiv 분야 필터, HF 트렌딩 모델
  - 출처 `#/sources` 또는 하단: 출처별 원문 목록(HN·GeekNews·Reddit 상위 글)
- 날짜 선택은 상단 시계 영역에서 한다.
- **모바일:** 900px 아래에서는 한 열로 바뀐다. 시안 v2에 이미 넣어 둔 규칙을 따른다.
- **움직임 줄이기:** `prefers-reduced-motion` 설정이 켜져 있으면 스캔 라인, 깜빡임, 게이지 애니메이션을 끈다.
- **모든 항목은 원문 링크로 연결한다.**
- **라이트·다크 모드** (내 판단으로 세부를 정함)
  - 처음 방문하면 기기 설정(`prefers-color-scheme`)을 따른다.
  - 사용자가 토글로 고른 값은 브라우저에 저장해 다음 방문에도 유지한다. 저장이 막힌 환경이면 기기 설정으로 돌아간다.
  - 페이지가 그려지기 전에 모드를 정해서, 다크 모드 사용자에게 흰 화면이 번쩍이지 않게 한다.
  - 두 모드 모두 본문 글자는 배경 대비 4.5:1 이상을 지킨다.

### 5.6 테마 구조

```
web/
  index.html            테마를 불러오는 껍데기
  core/                 데이터 불러오기, 주소 라우팅, 날짜·숫자 형식 (테마 공통)
  themes/
    aurora-hud/         E 테마: theme.css + render.js (화면 마크업을 테마가 직접 만든다)
  data/                 빌드 결과 JSON
```

- **화면 구조까지 테마가 정한다.** 테마마다 CSS만 다른 게 아니라 마크업 구성 자체가 다르기 때문이다. D는 벤토 카드고 F는 터미널 창이다.
- `core`는 테마에 "오늘 데이터 + 현재 화면 주소"를 넘기고, 테마는 그걸 그린다.
- 테마 선택은 지금은 설정값 하나로 한다. 나중에 전환 버튼을 붙일 수 있게 둔다.
- **라이트·다크 전환은 `core`가 맡는다.** 테마와 모드는 서로 다른 축이다.
  - `core`가 하는 일: `<html data-mode="light|dark">`를 관리하고, 저장된 값을 읽고 쓰고, 테마에 `toggleMode()`를 넘긴다.
  - 테마가 하는 일: 두 모드의 색을 CSS 변수 두 벌로 모두 제공하고, 토글 버튼을 자기 화면에 배치한다.
  - 새 테마를 추가할 때도 라이트·다크를 둘 다 갖춰야 한다.

## 6. 만드는 사람에게 맡기는 것

- 열기 점수와 게이지의 정확한 공식과 가중치. 단, 설명할 수 있어야 한다.
- 이슈 묶기 알고리즘의 세부 방식
- 불용어 목록, 재료 검색 토픽 목록의 세부 항목
- GitHub Models에서 쓸 모델. 무료 한도 안에서 한국어 품질이 괜찮은 것으로 고른다.
- 파일과 모듈의 세부 구조, 테스트 방식
- arXiv 수집 범위의 세부 사항. 원본처럼 최신 200편을 기본으로 한다.

## 7. 완료 기준

- 로컬에서 토큰 없이 `npm run collect && npm run build`를 실행하면 실제 오늘 데이터로 E 테마 페이지가 뜬다. 이때는 축소 모드이고, AI 요약은 없다.
- 출처를 하나 일부러 실패시켜도 나머지로 페이지가 만들어지고, 실패한 출처가 표시된다.
- 페이지에 지어낸 데이터가 없다.
- 데스크톱(1280px)과 모바일(375px)에서, 라이트와 다크 두 모드 모두 깨지지 않는다.
- 토글을 누르면 모드가 바뀌고, 새로고침해도 고른 모드가 유지된다.
- GitHub Actions 워크플로 파일이 준비돼 있다. 사용자가 새 저장소를 만들어 올리면 매일 수집과 배포가 돌아간다.
- 두 번째 테마를 추가할 때 `core`와 데이터 쪽을 고칠 필요가 없다. 빈 테마 하나를 끼워서 확인한다.
